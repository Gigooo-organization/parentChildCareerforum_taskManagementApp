# 勉強タスクアプリ体験ブース

親子キャリアフォーラムの10分体験で、参加者が勉強リストを自分らしく変えるアプリです。カタログは選択だけで反映し、自由なお願いはスタッフの承認後にClaude CodeまたはCodexへ送ります。

## 起動する

AIを使う体験には、macOSと`/usr/bin/sandbox-exec`が必要です。カタログだけならAIの認証やインターネット接続は不要です。初回の依存関係のインストールは、回線がある場所で済ませてください。

Nixとdirenvを使う場合は、リポジトリで次を実行します。

```sh
direnv allow
pnpm install --frozen-lockfile
```

direnvを使わない場合は、先に`nix develop`へ入ってください。Nixを使わない環境では、`package.json`のNodeとpnpmのバージョン条件を満たしてください。

起動のたびに前の作品を初期化します。残したいコードは、起動前に保存してください。

```sh
pnpm dev
```

ブラウザで`http://127.0.0.1:5173/`を開きます。スマホ枠のプレビューは、同じPCの5174ポートで動きます。会場ではこのPCのブラウザを参加者と一緒に操作してください。外部公開用のサーバーではありません。

ポートを変える場合は、メイン画面とプレビューに別々の番号を指定します。

```sh
BOOTH_PREVIEW_PORT=5184 pnpm dev --host 127.0.0.1 --port 5183 --strictPort
```

この場合は`http://127.0.0.1:5183/`を開きます。

## AIを用意する

当日使うPCに、選んだCLIをインストールしてログインします。認証情報をリポジトリや参加者への説明資料に貼り付けないでください。

Codexを使う場合は、次を実行します。既定のAIはCodexです。

```sh
codex login
BOOTH_AI_PROVIDER=codex pnpm dev
```

Claude Codeを使う場合は、次を実行します。

```sh
claude auth login
BOOTH_AI_PROVIDER=claude pnpm dev
```

AIを切り替えるときは、一度サーバーを終了してから起動します。再起動すると作品も初期化されます。既定のClaude設定ではmacOSのkeychain認証を利用します。独自の`CLAUDE_CONFIG_DIR`でkeychainだけを使う構成は未対応です。

## 参加者と体験する

1. カードを押し、質問の選択肢で仕様を決めます。色はブルー・ピンク・グリーン・オレンジ、ポイントは5・10・100から選べます。
2. **これで作る**を押します。カードが**作っている**へ移り、プレビューにローディングが表示されます。**完成**へ移ったら、チェックやタスク追加を試します。達成率や全件完了のお祝いも選べます。
3. 自由に変えたいときは、**作りたいものを追加しよう**へ入力し、**つぎに作るに追加**を押します。候補ボタンも使えます。個人情報は入力しないでください。入力しただけではAIへ送りません。
4. 追加したカードの**作る**を押すと、スタッフの確認待ちになります。スタッフが**スタッフ**を開き、アプリに関係する依頼か確認します。内容を確認してから**承認してAIへ送る**を押します。送らない場合は**送らずに取り消す**を押します。
5. 承認後はカードが**作っている**、成功後は**完成**へ移ります。参加者とプレビューを試します。依頼の全文や結果はカードを押して確認します。失敗・時間切れのカードは、**再試行**してスタッフの確認からやり直せます。

下の欄は入力用です。会話履歴を増やさず、進み具合はカンバンにまとめます。自分のアイデアは最大30件で、未完了のカードは容量整理で削除しません。

スタッフ操作にパスワードはありません。スタッフが隣で画面を見ながら承認してください。AIは1件ずつ実行し、生成結果の検査とコンパイルを含めて90秒で打ち切ります。失敗・時間切れ・取消では変更を戻します。復元できなかった場合は、リセットするまで変更操作を止めます。

回線が使えないときは、カタログのカードだけで体験を続けてください。AIはモデルAPIへの通信が必要です。

## 作品を保存して次の参加者へ渡す

起動・再起動・リセットで`.booth/app/`は作り直されます。コードと設定を残す場合は、操作前に保存先を作ってコピーしてください。

```sh
mkdir -p "$HOME/Desktop/booth-work"
cp -R .booth/app/src "$HOME/Desktop/booth-work/"
cp .booth/app/features.json "$HOME/Desktop/booth-work/"
```

参加者ごとに保存先の名前を変えてください。このコピーはコードと設定の保存です。画面上で追加したタスクやチェック状態は保存しません。

1. **スタッフ**を開き、**次の人へ**を押します。
2. 初期化する作品を確認し、**リセットする**を押します。
3. 自分のアイデアのカードが消え、プレビューがブルーの初期状態へ戻ったことを確認します。

実行中のAIがあれば、停止と復元を待ってから初期化します。`booth-app/`は初期テンプレートです。参加者の作品を保存するために直接編集しないでください。

## 変更を確認する

```sh
pnpm test --run
pnpm vize:check
pnpm vize:lint
pnpm vize:fmt
pnpm build
```

`vize:check`はVueの型チェックとサーバー側TypeScriptの型チェックを実行します。lintとformatの対象には、参加者アプリ・共通モデル・サーバーも含みます。整形を適用するときは`pnpm vize:fmt:fix`を使います。

`pnpm build`と`pnpm preview`は静的な画面の確認用です。設定API・AI・リセットを含む当日の体験には`pnpm dev`を使ってください。build単体には型チェックを含みません。

生成コードは`src/`のVue・TypeScript・CSSだけを変更できます。1回の変更は20ファイル・合計256KiBまで、変更後の編集対象ソース全体は40ファイル・256KiBまでです。CSSの`@import`と`url()`、プリプロセッサー、CSS Modules、Vueの外部ブロック参照とカスタムブロックは使えません。通常のCSSファイルはTypeScriptから読み込みます。

プレビューは別オリジンのiframeとCSPで親画面への干渉を制限します。ただし、ブラウザ全体の通信や、フレーム自身が外部URLへ移動することまで隔離する仕組みではありません。スタッフが承認内容と生成後の画面を確認してください。

当日PCとテザリング回線での確認は、[10分のリハーサル手順](docs/rehearsal.md)を使って行います。

## エディタを用意する

VS Codeでは`.vscode/extensions.json`の推奨どおり`ubugeeei.vize`を使います。Vueのコンパイル・型チェック・整形はVizeが担当します。
